#+TITLE: popup-window.el

popup-window.el provides the ~make-repl-popup~ macro, which wraps a
REPL-launching function so the REPL runs in a side window instead
of taking over your current window.  The buffer and its window are
cleaned up automatically when the REPL process exits.

Wrap your REPL-launching function with ~make-repl-popup~ and bind
the expansion to a command name with ~defalias~:

#+begin_src emacs-lisp
  (require 'popup-window)
  (require 'ielm)

  (defalias 'my/open-ielm (make-repl-popup #'ielm))
#+end_src

This is the preferred form.  The macro expands to an interactive
command with its own documentation, and ~defalias~ puts that
expansion directly in the function cell, so ~C-h f~ on
~my/open-ielm~, ~C-h k~ on any keybinding to it, and ~apropos~ all
show the wrapper's documentation.  Bind it to keys as usual:

#+begin_src emacs-lisp
  (global-set-key (kbd "C-c C-i") #'my/open-ielm)
#+end_src

The wrapped function works like the original one, including its
~&rest~ arguments, but any buffer it displays named =*...*= is
redirected to the side window configured by ~popup-window-side~ and
~popup-window-height~: the bottom of the frame by default,
taking 30% of the frame height.

When you invoke the wrapper without arguments and the wrapped
function is an interactive command that prompts for its
arguments, it runs through its own interactive form, so the prompt
still works: ~term~, for example, prompts for the program to run.

#+begin_src emacs-lisp
  (defalias 'my/term-popup (make-repl-popup #'term))
#+end_src

Change ~popup-window-height~ to customize the popup height — a
float between 0 and 1 is a fraction of the frame height, an
integer a fixed number of lines:

#+begin_src emacs-lisp
  (setq popup-window-height 0.5)
#+end_src

The popup appears at the bottom of the frame by default; set
~popup-window-side~ to ~top~ to display it at the top instead:

#+begin_src emacs-lisp
  (setq popup-window-side 'top)
#+end_src

Both options and their valid values can also be set interactively
through the Customize interface: ~M-x customize-option~ with the
option's name, or ~M-x customize-group popup-window~ to see them
together.

When the REPL process exits, its buffer is killed, which closes
the popup window with it.

* How it works

~make-repl-popup~ expands to an interactive lambda that, in three
steps:

1. Binds the ~display-buffer-alist~ so that any buffer whose name
   matches =\*.*\*= is shown via ~display-buffer-in-side-window~,
   then runs the wrapped REPL function.
2. Identifies the REPL buffer by diffing ~(buffer-list)~ before
   and after the call.
3. Attaches a process sentinel that kills the buffer when the
   process dies.

Caveats worth knowing:

- The ~display-buffer-alist~ binding matches every =*...*= buffer,
  so a REPL that opens auxiliary buffers as the buffer being
  focused will pop those up too.  Only the buffer that is popped
  up most recently among the new buffers is treated as the REPL.
- The REPL buffer is identified as the most recently used of the
  newly created buffers, so it relies on the REPL function being
  the one that displays its own buffer.
- The cleanup sentinel fires whenever the REPL process dies —
  normally or abnormally, a nonzero exit included — so the cleanup
  is guaranteed the moment the process is gone.  While the process
  lives, the popup stays.
- A buffer without a live process is left untouched; only the
  REPL buffer with its process gets the sentinel treatment.
- The wrapper's return value is the process sentinel, not the
  REPL buffer; reach the buffer through the wrapped function
  instead.

* Installation

This is a single-file package without a manifest yet.  Put
~popup-window.el~ on your ~load-path~ and ~(require 'popup-window)~.

* Running the tests

From the repository root:

#+begin_src shell
  emacs -Q --batch -L . -l test/popup-window-test.el -f ert-run-tests-batch-and-exit
#+end_src

A byte-compile check is also useful:

#+begin_src shell
  emacs -Q --batch -L . -f batch-byte-compile popup-window.el
#+end_src

This is an MVP; there is no build system or package manifest (no
Cask) yet.
